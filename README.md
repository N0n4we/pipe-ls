# Bash + jq 静态类型检查工具

## 项目定位

面向约定范式的 Bash + jq 代码提供静态类型检查，同时支持独立脚本和多种 CI 配置中的 Bash step。

产品的核心是一个与编辑器无关的静态分析引擎：通过 CLI 在本地和 CI 中检查代码，通过 LSP 在编辑器中提供即时反馈。

不以实现完整 Bash IDE 为首要目标，也不追求对任意 Bash 程序进行完整、可靠的类型推导。通过明确支持的代码范式，让常见的数据处理脚本获得可解释、可预测的检查能力。

## 希望解决的问题

Bash 经常通过命令、环境变量和管道传递文本，jq 则把这些文本作为结构化数据处理。错误容易发生在两者以及 CI 平台之间的边界上：

- 上游命令输出的 JSON 结构与下游 jq filter 的预期不一致。
- 字段可能缺失或为 null，却被当作必定存在的值使用。
- 普通文本、JSON 文本和 jq 原始输出被混用。
- jq 产生多个结果，下游却按单个结果处理。
- 环境变量、CI inputs 和 step outputs 缺乏明确的数据契约。
- 同一段脚本放进 CI 后，因 shell、工作目录或执行边界不同而出现问题。

目标是在代码运行前发现约定范围内的这些问题，并在原始代码位置提供清晰诊断。

## 核心使用场景

### 独立 Bash 脚本

检查符合约定范式的 `.sh` 文件，追踪命令输出、变量、管道与 jq 之间的数据流。

### CI 内嵌 Bash

从 CI 配置中识别 Bash 脚本单元，结合平台上下文进行分析，并将问题定位回配置文件，而不是临时生成的脚本。

初步考虑 GitHub Actions、GitLab CI 等平台。具体支持顺序待真实用例确定；不假定所有 CI 都是 YAML，也不假定所有脚本字段都运行 Bash。

## 初步能力方向

### 1. 为受限范式建立数据契约

Bash 变量在运行时主要承载文本。分析器需要区分文本的表示形式，以及文本所承载的数据结构，而不是简单把 Bash 变量视为 JSON 对象。

初步考虑描述：

- 普通文本与具有已知结构的 JSON 文本。
- JSON 的基本类型、对象字段、数组及可空性。
- jq 输出流的结果数量，例如零个、一个或多个结果。
- 命令、函数和 CI 输入输出的数据契约。

类型信息可以来自显式注解、schema、命令签名和有限的静态推导。具体声明语法与 schema 格式暂不确定。

### 2. 分析 Bash 与 jq 的连接关系

优先覆盖静态可识别的 jq filter，以及常见的变量赋值、管道和命令替换。

分析时需要考虑引号、子 shell 和 jq 参数对数据表示的影响，例如 `-r`、`-s`、`--arg`、`--argjson`。这些是需要逐步建模的语义，不意味着首版全部支持。

类型检查应关注下游是否满足使用条件，而不是一律把缺失字段或可空结果判为错误。

### 3. 将 CI 上下文作为分析输入

CI 支持分为两层：

- **脚本嵌入层**：识别脚本、处理字符串表示、维护源位置映射。
- **平台语义层**：提供 shell、工作目录、环境变量、执行边界和平台数据传递机制。

不同平台使用独立适配器。不能简单把所有脚本块拼接成一个 Bash 文件，也不能默认不同 step 共享 shell 变量。

CI 模板表达式需要单独处理。无法确定展开结果时，应明确保留不确定性，不能随意替换为某个字符串后声称分析可靠。

### 4. 明确检查边界

对动态命令、动态 jq filter、`eval`、无法解析的依赖等情况，优先给出 `unknown` 或“超出支持范围”的反馈。

需要区分：

- 已确定的类型错误。
- 依赖额外契约才能检查的问题。
- 当前不支持或无法确定的代码。

“不知道”不等于“已验证安全”。未知值的传播方式，以及严格模式是否阻止检查通过，后续再确定。

## 架构方向

```text
独立 .sh       GitHub Actions       GitLab CI       其他宿主
    │                │                 │              │
    └────────── 宿主适配器 / 脚本提取 ──────────────────┘
                            │
             脚本单元 + 执行上下文 + 源位置映射
                            │
                   Bash 解析与受限中间表示
                            │
           jq 分析 + 数据契约 + 数据流与类型检查
                            │
                   与编辑器无关的分析结果
                       ┌────┴────┐
                      CLI       LSP
```

设计原则：

- 分析核心不依赖 LSP 协议或某个编辑器。
- CI 适配器与类型检查核心分离。
- 源位置映射可以组合，支持从 jq filter 映射到 Bash 字符串，再映射到 CI 文件。
- 执行上下文显式传入，不直接假设开发者机器上的环境就是 CI 环境。
- 静态分析不执行待检查脚本，不为推断类型调用其中的业务命令。
- 优先复用成熟的解析器与协议库，不重复实现通用基础设施。

## 约定范式

- 脚本即函数

- 脚本开头附带类型声明

仅供参考：

```
#!/usr/bin/env bash
# @param  stdin: {"user_id": number, "token": string}
# @return stdout: {"status": "ok", "code": 0}
# @arg    $1 - force_update (boolean)
```

- 数据以 JSON 格式传递，使用 jq 排版 

- 数据以字符串参数形式而不是文件路径形式传递
